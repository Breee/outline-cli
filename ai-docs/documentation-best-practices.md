# Documentation Strategy

## Core Rule

**The CLI generates its own docs. Humans never hand-maintain reference content.**

```
make docs    # regenerates everything
```

That single command produces:
- CLI reference pages (from cobra command tree)
- `llms.txt` (structured index for AI discovery)
- `llms-full.txt` (all docs concatenated for full-context ingestion)
- LLM tool instructions (`.github/copilot-instructions.md`, `CLAUDE.md`, `.cursor/rules`)

If a new flag or command is added, `make docs` picks it up. No manual doc edits needed for reference content.

## What Gets Generated vs Hand-Written

| Content | Source | Maintained by |
|---------|--------|---------------|
| CLI reference (`docs/content/commands/`) | `cobra/doc` | **go code** |
| `llms.txt`, `llms-full.txt` | frontmatter in `docs/` | **go code** |
| LLM instructions (copilot, claude, cursor) | template in `cmd/docs.go` | **go code** |
| Guide pages (`docs/guide/`) | — | **humans** |
| Examples (`examples/`) | — | **humans** |

## Frontmatter Convention

Every doc page has:

```yaml
---
title: "Push Command"
description: "Push markdown to Outline."
llmsDescription: "outline push --path <path> --collection-id <id>. Flags: --path (default '.'), --collection-id (required), --publish (default true), --create-collection (default false)."
---
```

- `description` — human-readable, one sentence
- `llmsDescription` — technical, contains exact command syntax and behavior

## llms.txt Format

Follows [llmstxt.org](https://llmstxt.org/) spec:

```markdown
# outline-cli

> One-line summary

## Docs

- [Page Title](url): llmsDescription content
```

Generated by `outline docs generate --llms-txt`. Reads frontmatter from `docs/` directory.

## AI Tool Instructions

Generated files that tell AI coding assistants how to work with this project:

| File | Tool |
|------|------|
| `.github/copilot-instructions.md` | GitHub Copilot |
| `CLAUDE.md` | Claude Code |
| `.cursor/rules` | Cursor |

All generated from the same source. Content: project structure, build commands, architecture overview, key patterns.

## Site Build (GitHub Pages)

MkDocs Material renders the HTML site. The `hooks.py` post-build hook:
1. Copies raw `.md` files into site output (AI can fetch `page.md` directly)
2. Copies `llms.txt` and `llms-full.txt` into site root

CI pipeline: `make docs` → `mkdocs build` → deploy.

## Content Rules

1. Commands, not prose. Show `outline config set server_url https://...`, not "you can configure the server URL".
2. Tables for reference. Flags, env vars, config keys — always tables.
3. One concept per page.
4. Every example must work when copy-pasted.
5. No version numbers, dates, or "coming soon" in docs — they go stale.
